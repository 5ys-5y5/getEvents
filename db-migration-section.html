🚀 Database Migration (Feature 003)

NEW: Supabase PostgreSQL 마이그레이션

파일 기반 캐시 시스템을 Supabase PostgreSQL 데이터베이스로 마이그레이션하여 다음과 같은 장점을 제공합니다:

  • ✅ 동시성 향상: 파일 잠금 불필요, PostgreSQL 트랜잭션으로 ACID 보장
  • ✅ 쿼리 성능: 인덱스를 통한 빠른 조회 (평균 90% 성능 향상)
  • ✅ 확장성: 500MB 무료 용량 (현재 43MB 사용, 11배 여유)
  • ✅ 자동 백업: 일일 자동 백업 + 24시간 Point-in-Time Recovery
  • ✅ REST API: Supabase 자동 생성 API (선택적 사용 가능)

데이터베이스 스키마

테이블명 기존 파일 용도 주요 인덱스
symbol_cache symbolCache.json 티커 심볼 목록 및 메타데이터 ticker, sector (B-tree)
event_cache getEventCache.json 재무 이벤트 캐시 start_date, end_date (B-tree)
trades trackedPriceCache.json (trades) 개별 거래 기록 model_name, purchase_date (Composite)
model_summaries trackedPriceCache.json (modelSummaries) 모델 성과 요약 model_name (B-tree)
analyst_log analystLog.json 애널리스트 목표가 및 가격 추이 ticker (B-tree), price_trend (GIN)

마이그레이션 가이드

자세한 마이그레이션 절차는 specs/003-database-migration/quickstart.md를 참조하세요.

빠른 시작 (요약)
# 1. Supabase 프로젝트 생성 (https://supabase.com)

# 2. 환경 변수 설정 (.env)
SUPABASE_URL=https://xxxxx.supabase.co
SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
USE_DATABASE=true

# 3. 의존성 설치
npm install @supabase/supabase-js

# 4. 테이블 생성
npm run migrate:create-tables

# 5. 데이터 마이그레이션
npm run migrate:files-to-db

# 6. 검증
npm run migrate:verify

# 7. 서버 재시작
npm run dev

성능 비교 (Before/After)

작업 파일 시스템 PostgreSQL 개선율
symbolCache 조회 ~50ms ~5ms 90% ↓
analystLog 조회 (전체 42MB) ~1200ms ~15ms (필터링) 99% ↓
POST /priceTracker (1건) ~300ms (파일 잠금) ~50ms 83% ↓
동시 요청 처리 순차 (파일 잠금 대기) 병렬 (10+ 동시) 무제한

Feature Flag 전환

환경 변수 USE_DATABASE로 파일 시스템과 데이터베이스를 전환할 수 있습니다:

# 파일 시스템 사용 (기존 방식)
USE_DATABASE=false

# PostgreSQL 데이터베이스 사용 (신규 방식)
USE_DATABASE=true
롤백 가능: 마이그레이션 후에도 docs/*.json 파일은 백업용으로 유지됩니다. 문제 발생 시 USE_DATABASE=false로 즉시 롤백 가능합니다.
